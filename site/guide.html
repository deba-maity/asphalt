Player & developer instructions

A place to begin.

This page is static and works at a GitHub project subpath. No public release or repository URL is configured in this local delivery. Ask the owner for the actual repository; its root README contains complete verified commands and linked authoring/publishing/Android guides.

Play on Windows

  1. Choose the versioned windows-x86_64.zip, compare its SHA-256 with SHA256SUMS.txt from the same release.
  2. Extract All into a new folder, open the enclosed folder, then run AshenVow.exe. PCK data is embedded; keep README, BUILD.json, credits and licenses with it.
  3. Choose New Game. Follow E prompts and the objective. R heals; shrines refill and save. Continue returns to the checkpoint. Ordinary death retries; authored story progression is separate.

No Godot/Python/network/account is required to play. The candidate is unsigned; do not disable security software. APKs are Android apps, not Windows downloads. No Android game artifact exists.

Controls & progress

WASD move, mouse camera, Shift sprint, Space dodge, left/right mouse light/heavy, Ctrl guard/parry, Q lock, E interact, R heal, F later ability, Tab journal, Escape pause. Arrows/Enter navigate menus. Settings → Controls rebinds keyboard/mouse. Display selects 540p/720p/900p 3D and 30/60 caps; start 720p/30. Play offers Story difficulty, subtitles and reduced effects. Audio has separate bus levels.

Back up %APPDATA%\AshenVow\ while closed. Campaign: progress.json; prior valid file: progress.backup.json; settings: settings.cfg; log: logs\godot.log. Extract updates into a new game directory while retaining AppData. Chapter replay saves separately. Historical opening saves migrate with a retained original; future saves are refused safely.

Open and build the source

Required: Windows x64, PowerShell, Git, Python 3.10+ and exact Godot 4.7.2 stable standard GDScript. In a source checkout, change the first directory below to your actual checkout if different. Download helpers cache official SHA-pinned tools locally, never globally.

Set-Location 'C:\Users\debajyothi.m\wuk\ashen-vow'
powershell -File .\tools\setup.ps1 -Templates -ReleaseTools
powershell -File .\tools\test.ps1 -Campaign
powershell -File .\tools\build.ps1
# Commit reviewed source before portable packaging:
powershell -File .\tools\release.ps1

Project is game/project.godot. Import it in the pinned editor and press F5, or run powershell -File .\tools\launch.ps1 -Editor from the same root. Graphical launch is a deliberate action for the play machine; no game window is opened by tests. Build output is exports/windows; versioned ZIP/checksums/metadata are under exports/releases. Existing candidates are not overwritten. The root README explains -GodotPath, -TemplateDirectory, signing, deterministic timestamps and generated files.

Publish deliberately

First choose your actual authorized GitHub repository. Copy Code → HTTPS and inspect/configure origin; authenticate with GitHub CLI and push reviewed source. No account/repository is inferred here. Repository Settings → Pages → Source: GitHub Actions, environment github-pages. Configure github-release for optional publication.

Run Actions → Windows candidate, initially publish unchecked. Inspect its artifact, then explicitly publish a verified prerelease. Run Deploy download site with the exact public tag. The workflow hashes real uploaded assets before activating versioned links, and deploys only static site files. Find actual URLs in Settings Pages, deployment output and Releases. No hosted execution is claimed locally. Complete account/permission/environment/secret/update instructions: repository docs/publishing.md.

Troubleshooting & honest limits

No launch: verify complete extraction, Windows x64 and OpenGL3.3-capable driver. Keep error/security messages and logs; no security bypass. Low FPS: try 540p, shadows off, 30 cap; target Ryzen5500U hardware is untested. Wrong resolution: 3D height and window/HUD size are independent in Display settings.

Mouse/audio: Escape releases focus, Resume after releasing held actions; check rebindings, game volumes and Windows audio output. Transition failure: use checkpoint recovery and preserve logs. Damaged save: close, back up all AppData files, retain both progress copies. Automatic recovery validates the previous backup; never edit your only save.

Developer import/export: exact standard engine/templates must match; first import takes time. Check tools/logs. Indirect content needs all_resources plus content/*.json. Pages404: use exact deployed project subpath and successful Actions deployment. Missing release links are intentional before publication; private/draft/mismatched assets must fail activation.

Short campaign; multi-hour goal unmet. Simple hard-jointed art, synthesized audio and current camera/animation need human review. Full rendered campaign, physical inputs, sustained laptop performance and Android play remain not run. Headless campaign success is not visual or FPS proof.

For an issue, share BUILD.json, steps, chapter/objective/checkpoint, machine/driver/settings and logs/godot.log with the owner or actual repository Issues. Exclude personal files. Full recovery/authoring/acceptance procedures are in the repository docs.
