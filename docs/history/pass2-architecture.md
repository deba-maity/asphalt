# Architecture and ownership — pass two

The existing project, renderer, player/combat classes, opening scene construction and three autoloads are retained. `Session` owns plain progress and SaveStore; `Preferences` owns input/settings; `Sound` owns a bounded voice pool. Main owns the UI and transition coordinator. The same Fighter player node is detached during unloading and reparented into the next zone. Its combat model is reset from persistent progress; player identity remains constant across transitions and ordinary restarts. Only one zone remains active after a swap.

`Campaign` caches only the small JSON index: chapter names/IDs, zone paths, checkpoint positions and estimated speculative costs. It has no live scene references. Current-zone definitions supply dialogue, quests, objects, NPCs, encounters and rewards. `campaign_zone.gd` extends the original `ChapterWorld` helpers; the opening retains its own scene and content. Each later PackedScene references its relevant baked actor scenes so background loading retrieves actual local asset dependencies. Environment construction and activation remain explicit main-thread work.

## Transition state machine

`idle → requested → loading → ready → transitioning → idle`; errors enter `recovering`. A request while another is committed is refused. Near an objective exit the world speculatively requests at most one next resource set, under a configurable metadata budget (24 MB estimate by default). Triggering the gate/boat/story confirms the request, locks play, and shows honest loading progress.

The coordinator uses `ResourceLoader.load_threaded_request(path, "PackedScene", false, CACHE_MODE_REUSE)`, polls `load_threaded_get_status` once each process frame, and retrieves with `load_threaded_get` only after `THREAD_LOAD_LOADED`. These follow the [official ResourceLoader documentation](https://docs.godotengine.org/en/stable/classes/class_resourceloader.html) and [background-loading guidance](https://docs.godotengine.org/en/stable/tutorials/io/background_loading.html). Normal cache reuse keeps shared GDScript identities consistent; no growing array retains visited PackedScenes. Scene references are cleared after activation. Engine resource caching does not replace explicit ownership cleanup.

Logical cancellation marks a request stale, continues polling the underlying task, retrieves/discards its result, and releases references. It does not claim to cancel engine work. Missing resources fail before the old zone is unloaded. A malformed scene root is freed and progress rolls back; the recovery screen can reconstruct the saved checkpoint after a construction failure. The old progress snapshot is not replaced by the destination until construction succeeds.

Low-memory mode is the default: disable the old zone, disconnect its player death callback, detach the player, **free old nodes synchronously**, clear generated geometry/material caches, allow a release frame, then instantiate/activate the destination. Optional normal mode releases the old zone after constructing the new one. Settings file controls are `[streaming] low_memory=true` and `speculative_mb=24`; budget values are estimates, not a guarantee about physical GPU allocations. Both modes are covered by repeated unload/reload tests.

Old zones stop processing before being queued/freed. Lifetime guards prevent their callbacks from changing the new zone's state. Scene-owned NPCs, projectiles, corpses, wheel animation, coordinator, environment, signals and resources disappear with the scene. The persistent player's UI feedback connection is created once; its zone death signal is explicitly disconnected and rebound. No navigation mesh is rebuilt during transitions; these open authored lanes use local pursuit and static collision. More intricate future geometry will need authored navigation.

Metrics separate background-request elapsed time, PackedScene instantiation, `_ready` geometry/scripts, previous-zone release-frame time, total swap time, node count and available engine static-memory counters. Background resource work does not eliminate script, physics, shader or GPU activation costs. GPU/upload/shader timing is explicitly unmeasured in headless runs.

## Combat ownership and budgets

Fighter owns its model, articulated Figure, body, hurtbox, active-volume query and optional camera. Body layers: environment 1, player 2, enemies 3; hurtboxes: player 4, enemies 5; ash veil 6. Ashstep only removes the veil layer during its invulnerability; it does not phase through ordinary terrain. NPCs have no combat hurtbox. Attack windows and victim claims still prevent repeat per-tick damage.

EncounterCoordinator admits at most three nearby enemies and one committed attack lease. Waiting actors guard/reposition; accumulated waiting age rotates openings. Each zone owns its bounded enemies. Cleared fights stay cleared, corpses expire, and no dropped-object farm is created. Projectiles are scene-owned Node3D objects with a swept physics ray, lifetime limit and global cap of six. Static scenery is batched once into MultiMesh; generated caches are cleared on zone replacement. Actor meshes come from committed runtime scenes.

Attack data now includes anticipation, active window, recovery, damage/reach/arc, tracking window, posture/stamina effects, defense rules, pose and cue metadata. Guard, heavy guard break, parry, ordinary dodge, Ashstep, opening counter, healing, hit, story lock, phase protection and ordinary death have explicit exclusions. Elite pursuit reacts to evasions and repeated light strings. Halvek's phase change is protected and announced; no attackers spawn on top of the player.

## Progress and persistence

Schema 2 adds objective ID, bosses, completed chapters, Resolve/max-heals, resurrection state, canonical death/resurrection counters and ending/credits. Validate location membership, types, finite bounds, compatible body/abilities and the single canonical sequence. No executable-object deserialization. Schema 1 migrates by copying its established fields and deriving chapter-one completion; its original file is preserved before replacement. Future schemas are refused with an explicit message, even if an older backup exists. Temporary-write/flush/validation/replacement and previous-valid backups remain.

Authored death and resurrection commit their counters, flags, compatible chapter/zone/checkpoint and body state as one arrival transaction. Ordinary death never increments them. Story callbacks commit once; leaving mid-dialogue saves existing progress without claiming the unfinished event. Pausing preserves story UI and callback state. Camera/input restore on completion or skip. The betrayal's short fall uses a separate transition state and a token to reject stale/double skip callbacks. A chapter replay changes to a separate store; returning to title restores the original Continue store.
